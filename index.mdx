## Cabeçalhos e autenticação

Nas rotas autenticadas, envie a versão da API e um JWT. Nas rotas que enviam corpo JSON, inclua também o tipo de conteúdo:

```http
X-API-Version: 1
Authorization: Bearer <JWT>
Content-Type: application/json
```

O JWT deve pertencer a um usuário autorizado para executar a ação. Algumas rotas também exigem que o onboarding esteja concluído. As rotas de checkout público não exigem autenticação.

## Formato de resposta

As rotas que retornam conteúdo usam o mesmo envelope JSON:

```json
{
  "data": { ... },
  "success": true,
  "error": null
}
```

Em caso de erro:

```json
{
  "data": null,
  "success": false,
  "error": {
    "timestamp": "2026-07-28T10:30:00",
    "status": 422,
    "message": "Erro de validação",
    "path": "/api/products",
    "fields": [
      { "field": "name", "message": "Nome é obrigatório" }
    ]
  }
}
```

O campo `fields` é retornado em erros de validação e identifica os campos inválidos.

Algumas operações de exclusão ou alteração em lote retornam `204 No Content`, sem corpo.

## Códigos de status HTTP

| Código | Significado |
| --- | --- |
| 200 | Sucesso |
| 201 | Recurso criado com sucesso |
| 400 | Requisição inválida — verifique os campos enviados |
| 401 | JWT ausente, inválido ou expirado |
| 403 | Usuário autenticado sem permissão para a ação |
| 404 | Recurso ou versão de API não encontrada |
| 415 | Tipo de conteúdo não aceito |
| 422 | Erro de validação nos campos enviados |
| 500 | Erro interno no servidor |
